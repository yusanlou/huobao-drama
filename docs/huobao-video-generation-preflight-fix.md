# 第 2 镜点击生成立即失败：修复记录

2026-10-05

## 原因

《创可贴｜30 秒调优版》第 2 镜（分镜 ID 126）是换机位镜头，默认使用参考素材模式。此前的接续检查把“换机位”和“同机位连续动作”都设为必须上传、核对首帧，导致请求尚未提交就被拦截。

实际错误是“接续画面尚未核对或原数据已改变”。页面的通用错误转换又把这条较长的双语提示替换为“视频生成失败”，掩盖了原因。排查时第 1 镜已有完成记录，未发现这次点击对应的视频任务。

## 修改

| 情况 | 修复后的行为 |
| --- | --- |
| 换机位，参考素材或文字模式 | 可正常提交；保留人物状态、前镜完成情况和正在生成的任务检查 |
| 同机位连续动作 | 仍须使用首帧模式，并核对实际提交的首帧 |
| 换机位，主动选择首帧模式 | 核对首帧后才能提交；旧数据的确认不能沿用 |
| 准备条件不足 | 页面提前显示原因，点击时也显示具体缺项，不再统一报“视频生成失败” |

网页和 MCP 使用同一份检查。网页只在需要首帧时显示必填核对项；MCP 的只读预览增加 `continuity.requires_first_frame`，供客户端判断当前模式的要求。切换生成模式会清除旧首帧确认。

原服务端源码未改，已有剧本、分镜、视频未改。本次没有提交真实视频生成任务。

## 验证

- 用项目第 2 镜的真实数据回放网页生成处理函数：修复前未调用提交接口并显示通用错误；修复后调用模拟提交接口成功。
- 网页相关回归测试 35 项通过，MCP 全部 25 项通过；前端和 MCP 构建通过。
- 覆盖正常换机位、同机位缺首帧、首帧确认过期、人物状态冲突、前镜缺失、前镜仍在生成，以及模型仅支持参考素材的情况。
- 实际页面第 2 镜显示“可用参考素材和文字接续直接生成”；本地 MCP 重启后的只读预览返回空问题列表、`requires_first_frame: false`。
- 全量前端测试运行结果为 41 项通过、24 项失败，其中包含引用已不存在的 `app/pages/drama/…` 路径的旧结构测试。本次未逐项处理这些失败，不将相关回归通过表述为全量前端测试通过。

这些验证覆盖提交前检查和参数准备，未调用收费视频模型，不能替代实际成片验收。参考图模式不锁定真实首帧，生成后仍应查看人物站位和动作是否接上。

| T05 视频提示 | 强化运镜目的、色彩、光向、可见材质反应、时间顺序和逐字台词；分镜完成后只补缺失提示，保留已有提示 | 原批量接口仍含固定三秒指令；本次未修改其服务端源码 |
| T06 视频输入 | 两端使用相同预检：素材顺序及去重、引用对象、模型时长、首尾帧、视频/音频参考、原生音频、Wan 提示改写等；超限报错，不再静默截断 | 参数以当前仓库适配器能力为准；模型不支持的参数会拒绝或显示实际转换 |
| T07 结果检查 | 原视频页展示目标/分镜总时长、台词遗漏线索、粗略语音估时、前后镜描述、提交前预览和历史任务参数 | 估时只是提醒；未做配音实测、自动转写、语义连续性判定或厂商内部提示还原 |
| T08 原 Agent 接口 | MCP 增加改写、拆分、提示生成及回执查询；请求 key 防重复；长调用独立超时，异常后保留不明确状态 | `response_received` 只表示原请求返回，不代表创作质量合格或所有内容正确保存 |
| T09 原功能封装 | 补项目/集、资产、分镜、任务历史、上传绑定、风格、提示词、Skill、模型及应用设置；保留原媒体生成/合成工具 | 桌面专属桥接、原接口不具备的能力仍是缺口，详见下表 |

`shared/production.mjs` 只有两端共用的解析、参数整理和检查函数，没有独立进程、存储或编剧业务。网页仍直接访问原 API，关闭 MCP 不影响网页使用原能力。

原 `backend/src/` 的 59 个文件与实施前哈希完全一致。这里只修改了原服务端已有的可编辑配置。配置是全局生效的，会用于后续各项目的 Agent 请求，不会自动重写已有剧本或作品。

### 文字生成实测

使用当前配置的 `deepseek-v4-pro`，两份自编短文覆盖档案旁白、对白、动作、道具交接、换场、情绪、连续动作和异常现象。调用的是原改写和分镜 Agent，检查了写回的剧本与分镜。前后两轮共 12 次文字 Agent 调用，没有生成图片或视频。

| 样例 | 旧配置结果 | 本次最终结果 | 人工检查结论 |
| --- | --- | --- | --- |
| 固定光源下的异常投影 | 10 镜，110 秒 | 8 镜，合计 54 秒 | 台词和光影/动作描述更明确；第 2 镜仅 3 秒，台词粗估需 4 秒；顶灯、木盒与墙面投影的几何关系仍需修正 |
| 门口交接钥匙 | 4 镜，52 秒 | 10 镜，合计 54 秒 | 保留主要对白，右手递出、左手接过等连续性更明确；人物动机仍有表达不足，镜头是否过碎需要预演判断 |

这个对照比较的是整体入口改造：旧版没有新的制作要求块，新版明确传入 54 秒目标；它不是只换提示词的严格实验。样本少、只测一个模型，不能从总时长正确推导出专业程度或成品率达标。逐字文本写进提示也不等于视频模型一定正确发声。

## 4. 保留缺口

| 未解决事项 | 原因 / 当前处理 |
| --- | --- |
| 固定三秒批量提示、旧改写工具的每场 30–60 秒建议 | 位于不能修改的服务端源码；改写配置优先使用原文读取工具，单镜提示按实际时长；批量入口仍须人工检查 |
| 严格逐字配音、末尾不截断、精确成片 54 秒 | 本期只有原生音频控制和估时提醒；独立 TTS、ASR 校验、精细音轨/裁切属于方案后续范围 |
| 原内容/媒体覆盖和并发修改 | 原 Agent、生成接口直接回写；哈希和回执只辅助核对，不提供跨网页/MCP 的原子锁或草稿隔离 |
| 原批量状态和 Agent 恢复 | 批量状态在原服务端内存；Agent 无持久化调用 ID。超时或重启后不自动重发，须核对原内容和任务记录 |
| 桌面迁移、桌面更新 | 只有桌面桥接，没有原 HTTP API；不能用服务端更新接口冒充 |
| 修改既有剧集的模型绑定 | 原剧集 PUT 不支持这些字段；生成请求可显式指定模型配置 |
| 所有适配器可选参数完全透出 | 本期覆盖原网页和已实现的参考模式；Wan 的专用文件/链接模式等未全部封装。图片分块上传额外设 20 MiB 上限；不是原接口无上限透传 |
| 真实媒体质量与多模型兼容性 | 参数检查及假上游测试不能替代真实视频；本次按用户选择留待样片验收 |

## 5. 使用与回退

刷新原剧集页面，在“制作要求”填写目标与约束，保存后使用原改写、拆分按钮。视频页先看“检查”和提交预览，再发起生成。MCP 对应工具和参数见[扩展说明](../extensions/huobao-mcp/README.md)。

改造前的本地配置备份：`.local-backups/professional-config-before-20261004.json`。该目录不提交 Git；需要另机回退时须同时保管备份。恢复命令会先备份当前有效配置，再通过原 API 逐项恢复、读回验证，不调用 reset：

```sh
node scripts/deploy-production-config.mjs --restore .local-backups/professional-config-before-20261004.json
```

代码回退可从基线 release/tag 另建工作目录并重新构建，不必重置当前开发分支。**代码版本回退与有效配置恢复是两件事**；已有项目媒体不在此配置快照中。

常规复验命令：

```sh
npm --prefix extensions/huobao-mcp run typecheck
npm --prefix extensions/huobao-mcp test
npm --prefix extensions/huobao-mcp run test:backend
node --test frontend/tests/production-contracts.test.mjs
HUOBAO_FRONTEND_BUILD_DIR=.nuxt-validation npm --prefix frontend run generate
```

文字实测为显式选项 `npm --prefix extensions/huobao-mcp run evaluate:text -- --run`，会调用已配置的文字模型并产生相应费用，不属于常规自动测试。它会更新结果 JSON，重复评估前应保留需要比较的旧记录。

# 剧本与分镜加强：交付记录

2026-10-05。代码与配置已在本地更新并生效。原服务端源码未修改，当前《创可贴》的剧本、分镜、资产保持原样；未生成图片或视频。

**现在怎么用**

仍然使用现有“AI 改写 → 分镜拆分 → 视频提示词”入口。

- AI 改写：新版规则强调行动触发、人物反应的先后、转场线索，加入喜剧、人物戏和悬疑的对照示例。
- 分镜拆分：按“起始画面、动作与反应、结束画面”组织描述，重新设计取景和调度，明确保护揭晓时机。先做全片时长预算，再分配镜头；保存后检查工具返回的总时长。
- 单镜视频提示词：网页与 MCP 都补传已保存的首帧描述、末态、摄影和声音字段。原读取工具缺这些字段，以前只靠提示词要求“核对”并不足够。
- 视频制作页：展开“制作检查”，可以对照前镜末态、本镜起始画面、本镜末态及后镜起点，再查看人物、转场和揭晓的检查问题。页面已用当前项目实际验证。
- MCP：新增只读工具 `hb_get_production_checks`，与网页调用同一份检查实现。传项目、集和可选分镜 ID；不调用模型，不修改内容。

旧剧本和分镜不会自动重写。下次执行相应生成操作才使用新规则；整集“重新拆分”仍会替换已有分镜。

两组都满足了时长，因此不能据此宣称新版提高了成片成功率。具体可见的改善是：儿童喜剧的两次旧配置输出，都把镜中惊讶、转头或微笑提前写进起始画面；两次新版输出则在对应关键镜头保留“半合眼、未转头、尚未微笑”的起点，让视频有反应过程可以演。新版的镜头描述也明确给出了构图、动作阶段和结束状态。

初轮候选曾输出 64 秒与 68 秒，超出 54 秒目标，已保留失败记录。修正时间预算与保存后核对要求后，才完成上述两组各六个样例。没有把初轮失败从记录中抹掉。

**仍需人工判断的部分**

文字模型还没有达到免审核的程度。实测仍发现：个别起始画面夹带动作过程，少量镜头重复事件或有多余动作，个别剧本重复场景编号、补写短对白。比如新版档案样例的一次输出增加了重复形变段落，人物样例中仍有“从关心细节到过多动作”的倾向。它们应在文字审核时修改，不能因为总时长正确就进入视频生产。

这次交付的是规则、上下文和检查能力的加强，并未把语义审核做成强制保存关卡。检查区不会自动给“专业度分数”或品质通过结论。样例属于开发回归，与示例存在题材重合，不是独立泛化测试或盲评。实际表演、声音、镜面和剪辑效果仍需后续样片验证。

现有原生“批量补齐视频提示词”仍有服务端内置时序模板；本轮保留其兼容行为。整集拆分时已生成的提示词、单镜“重新生成”使用新版 Agent 规则。没有将未修改的批量路径描述成同等增强。

# 剧本转分镜：保留信息，也保留表现力

2026-10-05。对照对象：项目 4《创可贴》，第 1 集；当前剧本与分镜 111–117，共 7 段、30 秒。

## 原则

剧本提供要表达的内容，分镜决定观众怎样看到、听到这些内容。文字和镜头数量可以变，但帮助理解剧情、读懂反应、感受节奏或看清画面的信息，必须保留或转成有依据的等效表达。

可以删重复修辞、没有独立作用的解释。不能因为某句不是镜头语言，就删掉它承载的动机、情绪或画面细节。“害怕”可以转成停步、退缩或声音变化；具体选择要符合人物和上下文，不能任意加戏。

检查需要分两层：

1. 剧本 → 分镜：有没有把有用的信息、表演过程和揭晓顺序丢掉？
2. 分镜 → 实际生成输入：这些内容有没有进入视频提示词，或实际提交的首帧和参考素材？

只检查相邻镜头的位置和动作能否接上，回答不了这两个问题。前一轮接续修正着重解决位置错误，没有完整回查剧本的表演细节，这个缺口需要补上。

## 在原流程中怎么补

仍然是“AI 改写 → 拆分分镜 → 视频提示词 → 生成”，不新增用户操作步骤或另一套制作服务。

**拆分时做原文对照。** AI 先识别有用要点，再为每项找到镜头表达。对照格式为“原文短句 → 目标镜头和具体表达 → 保留／等效转译／合理删减／待解决”。可以跨镜实现，也可以在同镜并行，不要求一句拆一镜。

**生成提示词时再查一次。** 动态过程和必要声音要写入 video_prompt；静态外观可由实际提交、核对过的参考图承担。image_prompt、atmosphere、sound_effect 中写了什么，并不代表视频模型会自动收到。不能以同一个关键词出现就认定信息完整。

**删减必须说明依据。** 有用内容放不下，先合并重复表达、并行兼容动作、调整镜头预算。仍有冲突就指出原句和镜头，不能以“30 秒”为理由静默舍弃。只获准修改一个 video_prompt 时，遇到上游遗漏应报告具体字段；不要越权修改其他镜头，也不要提前塞入后面的揭晓。

**保存后给证据。** 返回简短对照表，重点列出转译、全部删减、有用细节的削弱与未解决项。依据实际读到的保存结果；未返回字段标为未核实。这个表是结果说明，不写入剧本或镜头表演正文，也不作为模型内部推理输出。

**原文歧义单独标记。** 不把可选导演设计算作确定遗漏；也不能以补全名义增加原剧本明确省略的过程。

| MCP 的 hb_get_production_checks | 返回同一份当前剧本和检查依据，继续只读；未改用单独的存储或业务流程。 |

没有修改 backend/src，没有新增数据库字段，没有重拆当前分镜，也没有提交生图或视频任务。

这次落实的是生成规则和可核对的依据，不是独立语义审查模型、全自动遗漏拦截或完整映射的持久化系统。AI 自查仍可能漏项；配置回读与代码测试不能证明创作完整率，更不能证明视频一定演得出来。

原生批量提示词接口也读取更新后的 Prompt/Skill，但其服务端请求仍有固定三秒分段指令，且原 read_storyboard_context 不返回 image_prompt/result/angle/movement。网页与 MCP 单镜入口已有补充数据；原生批量入口没有这份补充。本次规则要求它标明未核实项，不能宣称各入口的上下文完整性已经相同。该限制保留在不修改原服务端的边界内。

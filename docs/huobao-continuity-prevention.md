# 镜头接续：这次修了什么，后面怎么避免

2026-10-05

这次问题出在“每段单看自然，连起来却不像同一件事”。角色参考图主要约束长相，不能替代人物在上一段结束时的位置、姿态和动作进度。把任务改成顺序提交，也不会自动把这些状态传给下一段。

## 已落地的修改

| 环节 | 修改 | 解决什么问题 |
| --- | --- | --- |
| 重拆分镜 | 明确当前剧本是剧情依据，旧分镜只是旧记录；先建立全场空间和人物状态，再设计单镜 | 减少新剧本被旧分镜的事件、站位和节奏带偏 |
| 分镜内容 | 每镜增加接续表：固定布局、机位、切镜理由，以及每个人的起止位置、姿态、外观、是否入画 | 把“人在哪里、手放哪里、贴片属于谁”从笼统要求变成可对照的数据 |
| 画外人物 | 同样保留世界位置和状态；换机位只能改变是否看得见 | 避免角色下一镜突然出现，或从远处跳到近处 |
| 视频提交 | 网页和 MCP 共用检查，并将有效接续表转成文字约束，追加到实际提交的提示词 | 接续要求真正进入生成请求，而非只显示在检查面板 |
| 画面承接 | 同机位连续动作须用已核对首帧；换机位可用参考素材生成，选首帧模式时再核对 | 避免仍只传角色图、场景图，让模型重新摆人 |
| 批量生成 | 一个批次不能同时包含前后依赖镜头，包括隔着中间镜头的依赖 | 前镜尚未验收时，不抢先拍后镜；简单串行也不能绕过 |
| 过期确认 | 剧本、分镜、资产图片或前镜视频变化，旧核对失效；前镜仍在生成时也不能继续 | 避免拿旧尾帧接新版本 |
| 网页操作 | 接续表可编辑；提供上一段视频与下一段首帧对照，同机位可截取视频当前画面 | 人能完成核心操作，不依赖 MCP 在线 |

## 三种接法必须分开

| 情况 | 做法 |
| --- | --- |
| 同机位连续动作 | 核对前镜真实结尾，选取合格画面作为后镜首帧，保持人物与机位状态 |
| 换机位、时间连续 | 可按素材和文字接续直接生成；如需固定构图，再准备、核对新机位首帧。人物世界位置保持一致，不能把旧机位尾帧直接当作新机位画面 |
| 时间或地点跳切 | 明确省略的事件，重新建立状态。例如夜到晨不能沿用夜景尾帧。不能随便标成跳切来掩盖错误 |

第一镜另标“开场”。开场和明确时空跳切可独立生成；同机位连续动作先准备首帧。换机位默认参考图模式不强制首帧，仍检查前镜已完成及人物状态。

## 网页怎么用

1. 在“视频制作 → 镜头接续”查看接续表。以后拆分镜时要求 AI 一起填写；漏填或结构错误会阻止视频提交。旧项目不会自动删除或重拆，需补齐接续表。
2. 检查固定布局、起止状态和切镜方式。修改后点“保存接续表”。没有变化的状态沿用原文，不换同义说法。
3. 连续镜头先看上一段。如果实际拍错，先修前镜。不能把错误尾帧继续传下去。
4. 同机位可暂停在合适的画面，点“截取当前画面作为首帧”。换机位可直接使用参考素材；只有主动选择首帧模式时，才需要准备并上传新构图。
5. 使用首帧接续时，对照画面后勾选核对，再生成本镜。这个勾选只是本次接续确认，生成完成后仍需验收。

MCP 执行相同规则：用 `hb_write_storyboards` 保存接续表，`hb_inspect_video_input` 读取问题和当前核对快照；根据 `continuity.requires_first_frame` 判断当前模式是否需要首帧。需要时，实际查看前镜与首帧后，在 `video_options.continuity_review` 中提交快照和图片地址，以 `first_frame` 或 `first_last` 模式提交同一 `first_frame_url`。换机位的普通参考模式不填写虚假的首帧核对。

2026-10-05 修正：之前把所有换机位镜头也设为强制首帧，造成默认参考图模式无法生成。现在首帧门槛仅用于同机位连续动作或主动选择首帧模式；只支持参考素材的模型也可用于换机位镜头。参考图方式不锁定真实首帧，生成后仍需核对实际站位与动作。

## 实现边界

- 原 `backend/src/` 未修改，也没有新增数据库或第二套制作流程。接续表存在原分镜 `result` 字段的版本标记块内，原来的自然语言结束状态保留。网页和 MCP 读写同一份记录。
- 共享检查在 `shared/continuity.mjs`；实际提示词组装在 `shared/production.mjs`；网页入口为 `ContinuityPlan.vue`；MCP 在计划和派发前检查。原服务端 Prompt/Skill 配置通过原 API 部署。
- 这是**结构检查加画面核对入口**。相邻状态采用明确字段的相等比较，不是视觉识别。相同含义写成不同措辞也可能被拦截，需要统一表达。
- 程序不能证明首帧真实来自前镜，也不能证明勾选者认真看过，更不能保证视频模型完全听从提示词。后续可增加视觉比对辅助，但不能用它冒充成片验收。
- 改剧本会使接续核对失效；“新剧本是否充分反映到分镜”目前仍需审阅，源优先规则只是生成约束，不是自动语义验收。
- 防护覆盖更新后的网页和 MCP 入口。旧页面、直接调用原 HTTP 生成接口等仍可绕过；原后端没有事务式版本锁，跨入口同时修改仍有竞态。原合成接口也不会自动执行画面质量验收。
- 原生批量提示词接口仍有自己的实现；生成提交时会统一追加接续约束，但这不证明原提示词与接续表在语义上完全一致。

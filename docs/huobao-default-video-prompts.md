# 默认视频提示词修正

2026-10-05。修改面向所有项目的默认入口，当前项目 5 的剧本、分镜和素材没有重写。

## 原因与改动

| 原来 | 现在 |
| --- | --- |
| 默认拆分只加载分镜 Skill，完整的视频提示词要求留在另一套 Skill 里 | 两个原生 Agent 的 Skill 同步同一份视频提示词规范，网页和 MCP 的调用也带上该规范 |
| 非空提示词就被跳过，几十字摘要不会再补全 | 拆分保存后检查每条提示词的信息段；缺项时自动调用原 prompt_generator 定向补全 |
| 单镜生成拿不到完整的首帧、终态、摄影和声音字段 | 读取原服务端最新内容，把缺失字段和相邻镜头作为补充上下文传入 |
| 生成时不知道项目具体的风格预设 | 网页和 MCP 都读取项目风格及有效预设，供局部光色、材质设计使用 |
| 模型请求成功就容易被理解为生成完成 | 补全后再读回；仍缺项、内容未变化、其他字段变化时提示核对，不自动重试 |
| 跳切也追加“完成所有状态变化” | 时间跳切明确禁止补演已省略的事件，只执行本镜写明的可见变化 |

提示词按六部分组织：画面起点、动作节奏、摄影、光色与材质、声音、结束与衔接。每部分写镜头具体设计，不靠“电影感”“高清”或不可兑现的物理数值撑篇幅。两秒窗光转场可以短，复杂表演应写足。语音使用逐字台词。

程序检查的是标题下是否有实际文本、是否有占位内容、可识别的逐字台词是否遗漏；它不能判定材质是否合理、动作是否自然，或完整证明剧本信息没有丢失。检查结果始终保留 `semantic_approval: false`。旧提示词可能只是未按六段组织，提示缺项不等于判定旧文本完全没有相关信息。

## 使用方式

- 新项目：沿用“改写 → 提取资产 → 拆分分镜”。拆分直接应用完整规范，缺项补全自动执行，无需新增操作。
- 旧项目：视频制作页的“补全提示词”处理未按当前规范完整填写的镜头；勾选后仅重写所选镜头。单镜“重新生成”同样使用完整上下文和保存后检查。
- 补全只更新 `video_prompt`。上游分镜存在矛盾时，需要先修改对应分镜，不能靠提示词偷偷改变剧情、时长或接续表。
- 网页的补全在当前页面串行调用原 Agent。离开或刷新后不续发剩余请求；已发出的请求可能仍在服务端完成，应先刷新核对。它不是持久化后台任务。
- MCP 的 `hb_breakdown_storyboards` 自动执行同样的缺项补全；`hb_generate_video_prompts` 默认 `batch`，`single` 只处理一个 ID，均通过 `hb_get_call` 查询。显式 `native_batch` 保留旧原生异步接口作兼容，不具备客户端新增检查，不作为推荐入口。

已有提示词不会因为刷新页面被自动改写。新规范只在用户启动拆分、重写或补全时作用。

## 实现位置与边界

| 位置 | 职责 |
| --- | --- |
| `shared/video-prompts.mjs` | 规范正文、信息段检查、有限次原 Agent 补全与读回检查 |
| `shared/production.mjs` | 两端一致的调用内容、项目风格、已保存分镜上下文、实际视频请求中的接续说明 |
| `frontend/app/views/drama/episode.vue` | 默认拆分后的自动补全、手动批量和单镜入口；只访问原 Huobao API |
| `extensions/huobao-mcp/src/agent-calls.ts` | 使用同一补全函数，沿用调用回执、停止和不确定请求不重试的约束 |
| `backend/workspace/skills/{storyboard-breaker,prompt-generator/video-prompt}/SKILL*.md` | 两个原 Agent 的四语言运行配置，共 8 份同步规范 |
| `scripts/sync-video-prompt-policy.mjs` | 从共享正文更新上述 8 份配置；`--check` 防止两套规范漂移 |

没有修改 `backend/src/`，没有新增业务数据库或制作系统。网页不依赖 MCP 服务及其开关。并发修改检查为客户端读回检查，原服务端没有原子 CAS，不能宣称杜绝所有并发覆盖。

## 验证

- 前端与共享契约测试 29 项通过；MCP 测试 24 项通过；两端构建通过。
- 未修改的原服务端集成检查通过，包含网页/MCP 数据一致、MCP 关闭时网页仍可写入、24 份配置的部署和恢复；无媒体模型调用。
- 运行配置经原 API 部署，并逐项读回核对；8 份运行 Skill 与共享规范一致。部署前快照保存在 `.local-backups/default-video-prompts-20261005/`。
- 页面已实查“补全提示词”入口。当前项目仍为原有 7 镜、30 秒，没有触发生图或视频任务。
- 真实文本模型在独立临时数据库中运行三种题材，从原文改写到默认拆分，未手工润色生成结果：

| 题材 | 镜头数 | 总时长 | 六部分信息段齐全 | 每镜提示词字符数（仅描述结果，不作质量评分） |
| --- | ---: | ---: | ---: | ---: |
| 固定光源下的异常投影 | 7 | 54 秒 | 7/7 | 318–445 |
| 门口交接钥匙的人物戏 | 9 | 54 秒 | 9/9 | 228–349 |
| 镜中揭晓贴片的儿童喜剧 | 6 | 30 秒 | 6/6 | 302–360 |

样例已从“固定镜头＋动作概括”变为具体画面设计。例如人物戏交代手与钥匙的前后状态；儿童喜剧写出放慢凑近、屏息停住、呼吸起伏、灯光方向、遮挡与下镜接点。上述真实样例主要验证默认规范落地；项目风格补充及失败停止由契约测试验证。

这轮不等于成片质量验收。抽查仍有可优化处：档案样例第一镜 6 秒内安排较长旁白，留白可能不足；“柔和毛色”也不必然等于充分的材质表现。六段齐全不会自动启动媒体生成或标记语义通过。原始文字评估与检查记录保存在 `.local-backups/default-video-prompts-20261005/text-evaluation.json` 和 `text-readback-checks.json`，不覆盖用户作品。
